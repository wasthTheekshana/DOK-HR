# Project Manager Role — Design Spec

**Goal:** Add a new `project_manager` role with full operational and financial control across all sites (create/plan sites, define milestones, track project stage, score staff KPI), while blocked only from user/account management and system settings. No changes to existing tables' data — only additive columns and new tables.

**Architecture:** Extends the existing `sites` entity rather than introducing a parallel "project" concept — the current data model has no distinct project entity, and each site already maps 1:1 to what the business calls a "project." New tables for milestones and KPI scores; new nullable columns on `sites` and `tasks`. Follows existing patterns exactly (same `execute()` DB call style, same `requireRole` middleware, same role-filtered queries, same `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` migration block in `server/src/db/config.ts`).

**Tech Stack:** PostgreSQL, Express + TypeScript, React 18 + TypeScript + Tailwind CSS, Lucide React icons.

---

## Roles & Permissions

| Area | staff | supervisor | admin | system_admin | **project_manager** |
|---|---|---|---|---|---|
| Sites: view/create/edit (all sites) | — | own site (view) | ✅ | ✅ | ✅ |
| Staff/Team management | — | own site | ✅ | ✅ | ✅ |
| Tasks & Attendance (daily ops) | ✅ own | ✅ own site | ✅ | ✅ | view only (supervisor still owns daily ops) |
| Payroll / Invoices / financial reports | — | — | ✅ | ✅ | ✅ |
| Analytics | — | — | some | ✅ | — (not requested; excluded from v1) |
| User account management / system settings | — | — | ✅ | ✅ | ❌ |
| Project planning (milestones, headcount, timeline) | — | — | — | — | ✅ (new, PM-exclusive) |
| Staff KPI scoring & viewing | — | — | — | — | ✅ (new, PM-exclusive — not even admin) |

Key decisions:
- PM is effectively "admin + project planning + KPI, minus user/account management" — the one clean boundary requested.
- Supervisors are unaffected: they keep running day-to-day attendance/tasks on their own site. PM sits above them and does not take over daily ops.
- Project Planning and KPI screens are **PM-exclusive** — admin/system_admin do not get access in v1 (can be revisited later).

## Database Schema

All changes are additive (`ADD COLUMN IF NOT EXISTS` / `CREATE TABLE IF NOT EXISTS`), no existing rows or columns are modified.

### 1. Role enum
```sql
ALTER TABLE users DROP CONSTRAINT IF EXISTS users_role_check;
ALTER TABLE users ADD CONSTRAINT users_role_check
  CHECK (role IN ('admin','supervisor','staff','system_admin','project_manager'));
```
(In `server/src/db/config.ts`, alongside the existing migration block pattern.)

### 2. `sites` — planning columns
```sql
ALTER TABLE sites ADD COLUMN IF NOT EXISTS planned_start_date DATE;
ALTER TABLE sites ADD COLUMN IF NOT EXISTS planned_end_date DATE;
ALTER TABLE sites ADD COLUMN IF NOT EXISTS planned_headcount INTEGER;
```
No `stage` column — a site's current stage is derived from its milestones (see below), not stored separately, avoiding a field that can drift out of sync.

### 3. `project_milestones` (new table)
```sql
CREATE TABLE IF NOT EXISTS project_milestones (
  id          INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  site_id     INTEGER NOT NULL REFERENCES sites(id) ON DELETE CASCADE,
  name        VARCHAR(200) NOT NULL,
  description VARCHAR(1000),
  due_date    DATE,
  status      VARCHAR(20) DEFAULT 'not_started'
              CHECK (status IN ('not_started','in_progress','done')),
  sort_order  INTEGER DEFAULT 0,
  created_by  INTEGER REFERENCES users(id) ON DELETE SET NULL,
  created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX IF NOT EXISTS idx_pm_site ON project_milestones(site_id);
```
A site's "current stage" = the milestone with the lowest `sort_order` whose `status != 'done'` (or the last milestone if all are done).

### 4. `tasks` — milestone link
```sql
ALTER TABLE tasks ADD COLUMN IF NOT EXISTS milestone_id INTEGER
  REFERENCES project_milestones(id) ON DELETE SET NULL;
```
One milestone per task (simple nullable FK, matches how tasks are used today — no join table needed).

### 5. `staff_kpi_scores` (new table)
```sql
CREATE TABLE IF NOT EXISTS staff_kpi_scores (
  id          INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  staff_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  site_id     INTEGER NOT NULL REFERENCES sites(id) ON DELETE CASCADE,
  period      VARCHAR(20) NOT NULL,        -- e.g. '2026-07' (monthly)
  auto_score  NUMERIC(5,2),                -- computed from attendance % + task completion %
  pm_score    NUMERIC(5,2),                -- PM's finalized/adjusted score
  comments    VARCHAR(1000),
  scored_by   INTEGER REFERENCES users(id) ON DELETE SET NULL,
  created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE (staff_id, site_id, period)
);
CREATE INDEX IF NOT EXISTS idx_kpi_staff ON staff_kpi_scores(staff_id);
CREATE INDEX IF NOT EXISTS idx_kpi_site  ON staff_kpi_scores(site_id);
```
`auto_score` formula (v1): weighted average of attendance % and task completion % over the period, computed on-demand when PM opens the KPI screen for a period (not a background job). PM reviews and can override into `pm_score` with `comments`.

Also add `project_milestones` and `staff_kpi_scores` to the drop list in `server/src/scripts/seed.ts`.

## Backend

### New Files

**`server/src/controllers/projectPlanningController.ts`**
- `getSitesPortfolio` — `GET /api/project-planning/sites` (PM only) — returns all sites with: `planned_headcount`, actual headcount (count of `users` with that `site_id`), current stage (derived from milestones), milestone progress % (`done` milestones / total), average KPI for the site's latest period, `understaffed` flag + gap, and overall site `risk` badge (worst risk among its non-done milestones).
- `updateSitePlan` — `PUT /api/project-planning/sites/:id` (PM only) — updates `planned_start_date`, `planned_end_date`, `planned_headcount`.
- `getMilestones` / `createMilestone` / `updateMilestone` / `deleteMilestone` — `GET/POST/PUT/DELETE /api/project-planning/sites/:siteId/milestones` (PM only). `getMilestones` includes a computed `risk` field (`'red' | 'amber' | null`) per milestone based on `due_date` vs. today and `status`.
- `assignTaskToMilestone` — `PUT /api/project-planning/tasks/:taskId/milestone` (PM only) — sets `tasks.milestone_id`.

**`server/src/routes/projectPlanningRoutes.ts`** — all routes behind `authenticateToken, requireRole(['project_manager'])`.

**`server/src/controllers/kpiController.ts`**
- `getKpiScores` — `GET /api/kpi?site_id=&period=` (PM only) — returns per-staff `auto_score` (computed live from attendance/task data for the period) alongside any saved `pm_score`/`comments`.
- `saveKpiScore` — `POST /api/kpi` (PM only) — upserts `pm_score` + `comments` for a `(staff_id, site_id, period)`.
- `getKpiHistory` — `GET /api/kpi/history?staff_id=&site_id=&limit=6` (PM only) — last N periods' `pm_score` (or `auto_score` fallback) for the trend sparkline.

**`server/src/routes/kpiRoutes.ts`** — behind `authenticateToken, requireRole(['project_manager'])`.

Both routers registered in `server/src/app.ts`:
```typescript
app.use('/api/project-planning', projectPlanningRoutes);
app.use('/api/kpi', kpiRoutes);
```

### Modified Files
- **`server/src/db/config.ts`** — add the migration blocks above.
- **`server/src/schemas/validationSchemas.ts`** — add `'project_manager'` to the role `z.enum`.
- **`server/src/middleware/authMiddleware.ts`** — no changes needed; `requireRole` already takes an arbitrary role array.
- **Existing `sites`, `users`, `tasks`, `payroll`, `invoices` routes** — add `'project_manager'` into the `requireRole([...])` arrays wherever `'admin'`/`'system_admin'` currently appear for site/staff/financial access (per the permission table above). Daily-ops routes (attendance/task-entry-by-supervisor) are left as view-only for PM — PM is added to any `GET` routes but not `POST/PUT` task-entry routes.

## Frontend

### `client/src/components/Layout.tsx`
Add `'project_manager'` into existing nav item `roles` arrays for: Dashboard, Sites, Team, Payroll, Extra Units, Invoices, Reports (i.e., everywhere `'admin'` appears for operational/financial areas), matching the permission table. Do **not** add to Attendance/Task-entry write actions, Analytics, or Invoice Analysis (system_admin-only, out of scope).

Add two new nav items, visible to `project_manager` only:
```typescript
{ to: '/project-planning', label: 'Project Planning', icon: GitBranch, roles: ['project_manager'] },
{ to: '/kpi',               label: 'Staff KPI',        icon: Award,    roles: ['project_manager'] },
```

### New File: `client/src/pages/ProjectPlanning.tsx`
- **Landing (portfolio) view:** card/table per site — Site Name, Current Stage (derived from milestones), Headcount (actual / planned), Milestone Progress %, Average KPI, **Risk badge** (see below). Click a site to drill in.
- **Site detail view:** planned dates + headcount editable fields; milestone list (name, due date, status, drag-to-reorder via `sort_order`) with add/edit/delete; tasks-under-milestone assignment (dropdown on each task row pointing at a milestone).
- **Understaffing banner:** if a site's actual headcount < `planned_headcount`, show an inline warning banner on both the portfolio card and the site detail view (e.g. "Understaffed: 6 / 10").

### New File: `client/src/pages/StaffKpi.tsx`
- Site + period (month) selector.
- Table: Staff Name | Auto Score (computed) | PM Score (editable) | Comments (editable) | **Trend (sparkline)** | Save button per row.
- Clicking a staff row's trend sparkline expands a small chart of `pm_score` (falling back to `auto_score` where no `pm_score` was set) across the last 6 `period`s.

### Productivity additions

**1. Milestone risk flags** — computed field, no new schema. A milestone is flagged:
- 🔴 **red** if `due_date` has passed and `status != 'done'`
- 🟠 **amber** if `due_date` is within 7 days and `status != 'done'`
- Computed in `getMilestones`/`getSitesPortfolio` responses (`risk: 'red' | 'amber' | null`), not stored — always reflects current date vs. `due_date`.
- A site's overall risk badge on the portfolio view = the worst risk among its non-done milestones.

**2. Understaffing alerts** — computed field, no new schema. `getSitesPortfolio` compares actual headcount (`COUNT(users) WHERE site_id = :id`) against `planned_headcount` and returns `understaffed: boolean` + the gap. Surfaced as the banner described above; no separate notification/email channel in this pass (see "What This Does NOT Do").

**3. KPI trend view** — no new schema; `staff_kpi_scores` is already keyed by `(staff_id, site_id, period)`. New endpoint `getKpiHistory` — `GET /api/kpi/history?staff_id=&site_id=&limit=6` (PM only) — returns the last N periods' `pm_score` (falling back to `auto_score` when `pm_score` is null) ordered by `period`, for the sparkline.

## What This Does NOT Do

- Does not create a separate "project" entity distinct from `sites` — one site is one project.
- Does not give PM access to Analytics, Invoice Analysis, Target Performance, or Service Analysis screens (system_admin-only, unrelated to this feature).
- Does not give PM write access to daily attendance/task entry — supervisors keep running day-to-day ops; PM oversees via read access + planning/milestones.
- Does not expose KPI scores to staff, supervisors, or even admin/system_admin — PM-eyes-only in v1.
- Does not automate KPI scoring on a schedule — `auto_score` is computed on-demand when PM opens the screen for a period, not via a background job.
- Does not modify any existing table's existing columns or existing rows — all schema changes are additive.
- Does not send notifications, emails, or digests for risk flags or understaffing — these are surfaced only when PM views the portfolio/site screens, no push channel in v1.
- Milestone risk and understaffing flags are computed on read (not stored, not scheduled) — there is no background job scanning for at-risk sites.
