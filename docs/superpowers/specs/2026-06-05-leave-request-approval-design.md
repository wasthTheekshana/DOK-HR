# Leave Request & Approval Flow — Design Spec

**Goal:** Staff submit leave requests; supervisors approve or reject; admins can see all and override any decision. Purely informational — no automatic payroll impact.

**Architecture:** Standalone module — new `leave_requests` table, `leaveController.ts`, `leaveRoutes.ts`, and `Leave.tsx` page. Follows existing patterns exactly (same `execute()` named-param DB calls, same `requireRole` middleware, same role-filtered queries).

**Tech Stack:** PostgreSQL, Express + TypeScript, React 18 + TypeScript + Tailwind CSS, Lucide React icons, react-hot-toast.

---

## Roles & Permissions

| Action | staff | supervisor | admin |
|---|---|---|---|
| Submit leave request | ✅ | — | — |
| View own requests | ✅ | — | — |
| View site staff requests | — | ✅ | ✅ |
| Approve / Reject | — | ✅ (own site only) | ✅ |
| Override any decision | — | — | ✅ |
| View all requests (all sites) | — | — | ✅ |

## Database Schema

New table added via `ALTER TABLE` migration block in `server/src/db/config.ts` (same pattern as existing `responsible_person_id` migration):

```sql
CREATE TABLE IF NOT EXISTS leave_requests (
  id          INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  staff_id    INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  site_id     INTEGER NOT NULL REFERENCES sites(id) ON DELETE CASCADE,
  date_from   DATE NOT NULL,
  date_to     DATE NOT NULL,
  reason      VARCHAR(500),
  status      VARCHAR(20) DEFAULT 'pending'
              CHECK (status IN ('pending','approved','rejected')),
  reviewed_by INTEGER REFERENCES users(id) ON DELETE SET NULL,
  reviewed_at TIMESTAMP,
  admin_note  VARCHAR(300),
  created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX IF NOT EXISTS idx_lr_staff  ON leave_requests(staff_id);
CREATE INDEX IF NOT EXISTS idx_lr_site   ON leave_requests(site_id);
CREATE INDEX IF NOT EXISTS idx_lr_status ON leave_requests(status);
```

Also add `leave_requests` to the `tables` drop list in `server/src/scripts/seed.ts`.

**Key decisions:**
- `admin_note` — optional short message from reviewer (shown to staff on rejection)
- `reviewed_by` — tracks who acted (supervisor or admin)
- No `updated_at` — requests are reviewed once, not edited after submission
- `date_from > date_to` validated server-side

## Backend

### New Files

**`server/src/controllers/leaveController.ts`**

Four handlers:

#### `getLeaveRequests` — `GET /api/leave`
Query params: `status` (optional), `site_id` (optional, admin only)

Role filtering:
- `staff` → `WHERE staff_id = :callerId`
- `supervisor` → `WHERE site_id IN (SELECT id FROM sites WHERE supervisor_id = :callerId)`
- `admin` → all rows; optional `?site_id=` and `?status=` filters

Returns fields: `id, staff_id, staff_name, site_id, site_no, site_name, date_from, date_to, reason, status, reviewed_by, reviewer_name, reviewed_at, admin_note, created_at`

#### `createLeaveRequest` — `POST /api/leave` (staff only)
Body: `{ date_from, date_to, reason }`

Validation:
- Both dates required, `YYYY-MM-DD` format (`/^\d{4}-\d{2}-\d{2}$/`)
- `date_from <= date_to`
- `reason` max 500 chars

Inserts with `staff_id` and `site_id` from JWT (`req.user.id`, `req.user.site_id`).

Returns `201` with `{ id, message: 'Leave request submitted' }`.

#### `reviewLeaveRequest` — `PUT /api/leave/:id/review` (supervisor, admin)
Body: `{ status: 'approved' | 'rejected', admin_note?: string }`

- Supervisor: verifies the request's `site_id` is one they supervise
- Admin: can act on any request
- Sets `reviewed_by = callerId`, `reviewed_at = NOW()`
- Returns 404 if not found, 403 if supervisor tries to act on another site's request

#### `overrideLeaveRequest` — `PUT /api/leave/:id/override` (admin only)
Body: `{ status: 'approved' | 'rejected', admin_note?: string }`

Same as `reviewLeaveRequest` but no site ownership check — admin can override any decision including already-reviewed ones.

**`server/src/routes/leaveRoutes.ts`**

```typescript
import { Router } from 'express';
import { authenticateToken } from '../middleware/authMiddleware';
import { requireRole } from '../middleware/authMiddleware';
import { getLeaveRequests, createLeaveRequest, reviewLeaveRequest, overrideLeaveRequest } from '../controllers/leaveController';

const router = Router();

router.get('/',            authenticateToken, getLeaveRequests);
router.post('/',           authenticateToken, requireRole(['staff']), createLeaveRequest);
router.put('/:id/review',  authenticateToken, requireRole(['supervisor', 'admin']), reviewLeaveRequest);
router.put('/:id/override',authenticateToken, requireRole(['admin']), overrideLeaveRequest);

export default router;
```

Registered in `server/src/app.ts`:
```typescript
import leaveRoutes from './routes/leaveRoutes';
app.use('/api/leave', leaveRoutes);
```

## Frontend

### New File: `client/src/pages/Leave.tsx`

Single page, role-aware rendering. Uses existing `api` service, `useAuth` hook, `toast` for feedback.

#### Staff View
- Header: "My Leave Requests" + "New Request" button
- Table: Date Range | Reason | Status badge | Reviewer Note
- "New Request" opens a modal with: date_from input, date_to input, reason textarea (max 500 chars), Submit button
- Client-side guard: `date_from > date_to` shows inline error before submit

#### Supervisor View
- Two tabs: **Pending** (badge count) | **All**
- Table: Staff Name | Site | Date Range | Reason | Actions
- Approve (✓) / Reject (✗) buttons on pending rows
- Clicking either opens a small confirm modal with an optional "Note" field
- After action, list refreshes automatically

#### Admin View
- Filter bar: Site dropdown | Status dropdown (All / Pending / Approved / Rejected)
- Table: Staff Name | Site | Date Range | Reason | Status badge | Reviewed By | Actions
- Pending rows: Approve / Reject buttons
- Already-reviewed rows: Override button (opens same confirm modal)

#### Status Badges
Matches existing badge patterns in the codebase:
- `pending` → yellow (`bg-yellow-100 text-yellow-800`)
- `approved` → green (`bg-green-100 text-green-800`)
- `rejected` → red (`bg-red-100 text-red-800`)

## What This Does NOT Do

- No email or push notifications (informational badge only via pending count in nav)
- No payroll integration — leave is purely a record
- No file attachments
- No leave balance / quota tracking
- Supervisors cannot submit leave requests (only staff can)
